* C Study Guide
Twelve files on C. This page gives the reading order, what to do with each file, and links to the sections that matter most. Follow links with =C-c C-o= (cursor on the link) and return with =C-c &=.

** How to use this folder
- [[file:00_learn.org][00_learn]] is a quick reference for syntax. Use it for lookups; it is not part of the study sequence.
- Files 01 to 11 are the study sequence. Each file ends with a *What to remember* checklist.
- Each file refers to the others by name (for example =02_types.org=). Keep them in one directory.

** Method for each file
1. Skim the headings (=S-TAB= cycles the whole outline), then read the sections in order.
2. Type the examples instead of pasting them. Compile with the flags from the next section and read every warning.
3. Before running an example, predict its output; when the prediction is wrong, find out why.
4. Break each example on purpose (overflow it, free it twice, drop the mutex) and read what the tools report.
5. Do the practice items, then reread *What to remember* and tick the file off below.

** Setup
*** Naming
The files are meant to carry a numeric prefix so they sort in reading order. If they still have their original names, run this once from the C directory:

#+begin_src sh
mv learn.org 00_learn.org
mv language.org 01_language.org
mv types.org 02_types.org
mv functions.org 03_functions.org
mv memory.org 04_memory.org
mv data-structures.org 05_data-structures.org
mv standard-library.org 06_standard-library.org
mv io-and-errors.org 07_io-and-errors.org
mv macros.org 08_macros.org
mv preprocessor.org 09_preprocessor.org
mv toolchain.org 10_toolchain.org
mv concurrency.org 11_concurrency.org

# update the textual cross-references inside the files (types.org becomes 02_types.org)
perl -pi -e 'BEGIN { %n = (language=>"01_language", types=>"02_types", functions=>"03_functions", memory=>"04_memory", "data-structures"=>"05_data-structures", "standard-library"=>"06_standard-library", "io-and-errors"=>"07_io-and-errors", macros=>"08_macros", preprocessor=>"09_preprocessor", toolchain=>"10_toolchain", concurrency=>"11_concurrency") } s/(?<![\w-])([a-z-]+)\.org/exists $n{$1} ? "$n{$1}.org" : "$1.org"/ge' [0-9][0-9]_*.org
#+end_src

The perl command rewrites only names that have no prefix yet, so running it twice does no harm. The glob =[0-9][0-9]_*.org= leaves this README untouched.

*** A scratch directory and a compile-and-run helper
#+begin_src sh
mkdir -p ~/scratch/c && cd ~/scratch/c

# add to your shell config (zsh/bash)
cx() {
    cc -std=c17 -Wall -Wextra -Wpedantic -g -fsanitize=address,undefined "$1" -o "${1%.c}" -lm \
        && "./${1%.c}"
}

cx hello.c
#+end_src

This compiles with warnings and with AddressSanitizer and UndefinedBehaviorSanitizer on, which is the right default while learning. Some examples need extra flags (for example =-pthread= in step 11); the file says so.

** The sequence
*** 01: language
File: [[file:01_language.org][01_language]]

The rules of the language itself: what is undefined, how expressions are evaluated, how to read declarations, and what scope, storage duration, and linkage mean. Everything after this assumes it.

Key sections:
- [[file:01_language.org::*2. Categories of behavior][§2 Categories of behavior]]
- [[file:01_language.org::*4. Evaluation order and sequence points][§4 Evaluation order and sequence points]]
- [[file:01_language.org::*5. Reading declarations][§5 Reading declarations]]
- [[file:01_language.org::*6. Scope, storage duration, and linkage][§6 Scope, storage duration, and linkage]]
- [[file:01_language.org::*8. Statements and control flow][§8 Statements and control flow]]

Practice:
- Write declarations for "array of 3 pointers to functions taking =int= and returning =int=", then the =typedef= version; read each aloud with the right-to-left rule.
- Compile a program that overflows a signed =int= with =-fsanitize=undefined= and read the report.

*** 02: types
File: [[file:02_types.org][02_types]]

Integer widths, overflow, promotions and conversions, floating point, and byte representation. Most subtle C bugs live here, and =memory=, =io-and-errors=, and =concurrency= refer back to it.

Key sections:
- [[file:02_types.org::*2. Signed overflow and unsigned wrap][§2 Signed overflow and unsigned wrap]]
- [[file:02_types.org::*3. Integer promotions and the usual arithmetic conversions][§3 Integer promotions and the usual arithmetic conversions]]
- [[file:02_types.org::*5. Floating point][§5 Floating point]]
- [[file:02_types.org::*11. Type punning and representation][§11 Type punning and representation]]
- [[file:02_types.org::*13. printf and scanf format specifiers][§13 printf and scanf format specifiers]]

Practice:
- Predict the result of every expression in §3 before running it; then compile with =-Wsign-compare -Wconversion= and read the warnings.
- Implement =put_u32_be= / =get_u32_be= and test a round trip, including values with the top bit set.

*** 03: functions
File: [[file:03_functions.org][03_functions]]

Passing, returning, and callbacks: by-value semantics, several results, function pointers with =void *= context, and variadic functions.

Key sections:
- [[file:03_functions.org::*2. Parameters are passed by value][§2 Parameters are passed by value]]
- [[file:03_functions.org::*3. Returning values][§3 Returning values]]
- [[file:03_functions.org::*4. Function pointers and callbacks][§4 Function pointers and callbacks]]
- [[file:03_functions.org::*5. Variadic functions][§5 Variadic functions]]

Practice:
- Write =each(array, n, fn, ctx)= and use a context struct to compute the sum and the maximum in one pass.
- Return a =struct divmod=, then rewrite it with out-parameters and compare the call sites.

Key sections:

- [[file:04_memory.org::*11. Finding memory bugs][§11 Finding memory bugs]]

*** 05: data-structures
File: [[file:05_data-structures.org][05_data-structures]]

Building structures from arrays, structs, and unions: dynamic arrays, tagged unions, lists, hash tables, opaque types.

Key sections:
- [[file:05_data-structures.org::*2. Dynamic arrays][§2 Dynamic arrays]]

File: [[file:06_standard-library.org][06_standard-library]]

The parts of the library people misuse: =string.h=, number parsing, =qsort=, =time.h=, signals.

Key sections:

- Replace every =strcpy= / =strcat= in a toy program with a bounded alternative.

** Reading notes
- Code blocks are =#+begin_src c= (or =sh=, =make=, ...). Many are fragments, not complete programs: wrap them in a =main= and add the headers they use.
- The C code was compiled and run with GCC on Linux, mostly inside small test programs. Commands for other tools (Clang sanitizers, CMake, gdb, WebAssembly) were not run. Features from C23 are marked and need a recent compiler.
- Tables and the *What to remember* sections are meant for review; after finishing a file, come back to those.
- When something in a file contradicts your compiler or the standard, trust the standard and the compiler's documentation, and fix the file.
