#+title: C Data Structures
#+startup: overview

* C Data Structures
C provides arrays, structs, unions, and pointers. Everything else is built from them. The standard library has no vector, list, or hash table.

** 1. Arrays
#+begin_src c
int a[5] = {1, 2, 3};          /* remaining elements are 0 */
int b[] = {1, 2, 3};           /* length 3, deduced */
int grid[3][4];                /* 3 rows of 4 ints, row-major in memory */
grid[1][2] = 5;

size_t n = sizeof b / sizeof b[0];   /* 3: valid only where b is a real array */
#+end_src

Array length is fixed at compile time (variable-length arrays exist since C99, are optional since C11, and are risky for large sizes). No bounds checking happens: =a[5]= on a 5-element array is undefined behavior.

** 2. Dynamic arrays
A growable array is a struct with a pointer, a length, and a capacity.

#+begin_src c
#include <stdlib.h>

typedef struct {
    int *data;
    size_t len, cap;
} IntVec;

int intvec_push(IntVec *v, int x) {
    if (v->len == v->cap) {
        size_t ncap = v->cap ? v->cap * 2 : 4;
        int *p = realloc(v->data, ncap * sizeof *p);
        if (p == NULL) return -1;       /* v is unchanged and still valid */
        v->data = p;
        v->cap = ncap;
    }
    v->data[v->len++] = x;
    return 0;
}

IntVec v = {0};                          /* realloc(NULL, n) acts like malloc */
intvec_push(&v, 42);
free(v.data);
#+end_src

Doubling gives amortized O(1) push. A production version should also guard the =ncap * sizeof= multiplication against overflow.

** 3. Structs and layout
#+begin_src c
struct point { double x, y; };

struct point p = { .x = 1, .y = 2 };
struct point q = p;                      /* copies every member */
#+end_src

The compiler inserts padding for alignment, so field order affects size:

#+begin_src c
struct a { char c; int i; char d; };     /* typically 12 bytes with 4-byte int */
struct b { int i; char c; char d; };     /* typically 8 bytes */
#+end_src

Do not compare structs with =memcmp= (padding bytes are unspecified) or with ~==~ (not defined for structs). Compare field by field. =offsetof(type, member)= from =<stddef.h>= gives a member's offset.

** 4. Tagged unions (variants)
A =union= stores one of its members at a time. Pair it with a tag to know which.

#+begin_src c
enum shape_kind { SHAPE_CIRCLE, SHAPE_RECT };

struct shape {
    enum shape_kind kind;
    union {
        struct { double r; } circle;
        struct { double w, h; } rect;
    } as;
};

double area(const struct shape *s) {
    switch (s->kind) {
    case SHAPE_CIRCLE: return 3.14159265358979 * s->as.circle.r * s->as.circle.r;
    case SHAPE_RECT:   return s->as.rect.w * s->as.rect.h;
    }
    return 0.0;
}
#+end_src

Reading a member other than the one last written is only partly defined (type punning through unions is allowed in C, not in C++). With =-Wall=, GCC and Clang warn when a =switch= on an enum misses a case, which gives you some of the exhaustiveness checking a language with sum types provides.

** 5. Enums and flags
An =enum= is a set of named integer constants.

#+begin_src c
enum color { RED, GREEN, BLUE };         /* 0, 1, 2 */
#+end_src

Bit flags combine in an unsigned integer:

#+begin_src c
enum {
    PERM_READ  = 1u << 0,
    PERM_WRITE = 1u << 1,
    PERM_EXEC  = 1u << 2,
};

unsigned perms = PERM_READ | PERM_WRITE;
if (perms & PERM_WRITE) { /* writable */ }
perms &= ~PERM_WRITE;                    /* clear a flag */
perms ^= PERM_EXEC;                      /* toggle a flag */
#+end_src

** 6. Linked lists
#+begin_src c
struct node {
    int value;
    struct node *next;
};

int push_front(struct node **head, int v) {
    struct node *n = malloc(sizeof *n);
    if (n == NULL) return -1;
    n->value = v;
    n->next = *head;
    *head = n;
    return 0;
}

void free_list(struct node *h) {
    while (h != NULL) {
        struct node *next = h->next;     /* read before freeing */
        free(h);
        h = next;
    }
}
#+end_src

A =struct node **= lets the function update the caller's head pointer. Lists have poor cache locality, so a dynamic array is usually faster unless you need cheap insertion in the middle with stable pointers.

** 7. Hash tables
There is none in the standard library. Options: write one, or use a library (for example =uthash=, =khash= from klib, or =stb_ds=). The usual design is an array of buckets (chaining) or open addressing, plus a hash function:

#+begin_src c
#include <stdint.h>

uint64_t fnv1a(const char *s) {
    uint64_t h = 14695981039346656037ULL;
    for (; *s; s++) {
        h ^= (unsigned char)*s;
        h *= 1099511628211ULL;
    }
    return h;
}

/* bucket index: fnv1a(key) % nbuckets  (or & (nbuckets - 1) for a power of two) */
#+end_src

You also need a resize policy (grow when the load factor passes a threshold) and an ownership rule for keys and values.

** 8. Opaque types
Hide the representation behind a forward-declared struct. Callers hold only pointers.

#+begin_src c
/* stack.h */
typedef struct Stack Stack;
Stack *stack_new(void);
int    stack_push(Stack *s, int x);
void   stack_free(Stack *s);

/* stack.c */
struct Stack { int *data; size_t len, cap; };
#+end_src

Callers cannot access fields or allocate the struct on their own, which lets you change the representation without touching client code.

** 9. Ownership conventions
C does not track ownership; you do, by convention and documentation. Decide for every pointer who allocates, who frees, and how long it stays valid. A common style: =*_new= / =*_free= pairs, functions taking =const= pointers do not retain them, and functions that store a pointer say so.

** 10. Choose the structure for the job
| Need                             | Common choice                     |
|----------------------------------+-----------------------------------|
| Fixed-size sequence              | Array                             |
| Growable sequence                | Dynamic array (pointer, len, cap) |
| Fixed named fields               | =struct=                          |
| One of several shapes            | Tagged union                      |
| Set of options                   | =enum= or bit flags               |
| Frequent insert/delete in middle | Linked list                       |
| Key-value lookup                 | Hash table (library or your own)  |
| Hide representation              | Opaque struct pointer             |

Start with arrays and structs. Add the rest when measurements or the problem call for them.
