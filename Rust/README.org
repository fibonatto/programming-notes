* Rust Study Guide
Fifteen files on Rust. This page gives the reading order, what to do with each file, and links to the sections that matter most. Follow links with =C-c C-o= (cursor on the link) and return with =C-c &=.

** How to use this folder
- [[file:00_learn.org][00_learn]] is a quick reference for syntax. Use it for lookups; it is not part of the study sequence.
- Files 01 to 14 are the study sequence. Each file ends with a *What to remember* checklist.
- Each file refers to the others by name (for example =03_ownership.org=). Keep them in one directory.

** Method for each file
1. Skim the headings (=S-TAB= cycles the whole outline), then read the sections in order.
2. Type the examples instead of pasting them. Compile them and read every warning and error in full.
3. Before running an example, predict its output or whether it compiles; when the prediction is wrong, find out why.
4. Break each example on purpose (use a moved value, take two mutable borrows, send an =Rc= to a thread) and read the compiler's message.
5. Do the practice items, then reread *What to remember* and tick the file off below.

The files are meant to carry a numeric prefix so they sort in reading order. If they still have their original names, run this once from the Rust directory:

#+begin_src sh
mv learn.org 00_learn.org
mv language.org 01_language.org
mv types.org 02_types.org
mv ownership.org 03_ownership.org
mv functions.org 04_functions.org
mv data-structures.org 05_data-structures.org
mv traits-and-generics.org 06_traits-and-generics.org
mv iterators.org 07_iterators.org
mv io-and-errors.org 08_io-and-errors.org
mv standard-library.org 09_standard-library.org
mv modules.org 10_modules.org
mv macros.org 11_macros.org
mv concurrency.org 12_concurrency.org
mv unsafe-and-ffi.org 13_unsafe-and-ffi.org
mv toolchain.org 14_toolchain.org

# update the textual cross-references inside the files (ownership.org becomes 03_ownership.org)
perl -pi -e 'BEGIN { %n = (language=>"01_language", types=>"02_types", ownership=>"03_ownership", functions=>"04_functions", "data-structures"=>"05_data-structures", "traits-and-generics"=>"06_traits-and-generics", iterators=>"07_iterators", "io-and-errors"=>"08_io-and-errors", "standard-library"=>"09_standard-library", modules=>"10_modules", macros=>"11_macros", concurrency=>"12_concurrency", "unsafe-and-ffi"=>"13_unsafe-and-ffi", toolchain=>"14_toolchain") } s/(?<![\w-])([a-z-]+)\.org/exists $n{$1} ? "$n{$1}.org" : "$1.org"/ge' [0-9][0-9]_*.org
#+end_src

The perl command rewrites only names that have no prefix yet, so running it twice does no harm. The glob =[0-9][0-9]_*.org= leaves this README untouched.

*** A scratch project and a helper for single files
#+begin_src sh
cargo new --bin ~/scratch/rs && cd ~/scratch/rs      # a project for examples with several files or dependencies
cargo run

# add to your shell config (zsh/bash): compile and run one file in debug mode,
# which keeps overflow checks and debug assertions on
rs() {
    rustc --edition 2021 -g "$1" -o "${1%.rs}" \
        && "./${1%.rs}"
}

rs hello.rs
#+end_src

Use =cargo= for anything that needs a crate (=serde=, =rayon=, =tokio=, =thiserror=, =anyhow=). Many snippets in these files are fragments: put them inside =fn main()= and add the =use= lines they need.

** Reading notes
- Code blocks are =#+begin_src rust= (or =sh=, =toml=, ...). Many are fragments, not complete programs: put them in =fn main()= and add the imports.
- These notes were written without a Rust compiler at hand, so the examples were reviewed by hand and not all compiled. When one fails, =cargo check= and =rustc --explain EXXXX= will say why; treat it as a bug in the file and fix it.
- Features tied to a version are marked (for example the 2024 edition, =LazyLock= in 1.80, =thread::scope= in 1.63); on an older toolchain, update with =rustup update=.
- Tables and the *What to remember* sections are meant for review; come back to them after finishing a file.
- The C notes use the same layout. Reading the matching C file first (=04_memory= against =03_ownership=, =10_toolchain= against =14_toolchain=) shows what Rust changes and what stays the same.
